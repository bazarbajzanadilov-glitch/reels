# Запуск на сервере

Подготовлен Docker Compose: web, отдельный worker и дополнительный Caddy для HTTPS. Публикация и платная генерация автоматически не выполняются.

Для первого теста с 1080p разумная стартовая конфигурация — 4 vCPU, 8 ГБ RAM, 30–50 ГБ свободного SSD, Linux и Docker Compose v2. Это ориентир, а не измеренная гарантия скорости. При 2 vCPU/4 ГБ начать с `RENDER_WORKERS=1`. Локальный Whisper увеличивает нагрузку и устанавливается отдельно.

## Подготовка

1. На этом Mac: `.venv/bin/python deploy.py package`. Получится архив исходников в `releases/`, без `.env`, ключей, роликов, истории и кэша.
2. Перенести архив на сервер и распаковать в отдельный каталог.
3. Скопировать `.env.example` в `.env`, заполнить ключ, надёжный пароль и домен. Ограничить права: `chmod 600 .env`. Основному ключу нужны права генерации и управления ограниченными ключами.
4. Создать каталоги и выдать доступ пользователю контейнера:

```sh
mkdir -p jobs cache .models backups
sudo chown -R 10001:10001 jobs cache .models backups
sudo chmod 700 jobs backups
```

Если изменены APP_UID/APP_GID, использовать соответствующие числа. Существующую историю переносить из проверенной резервной копии; после переноса также проверить владельца закрытых файлов. Исходники отдельно от приватного backup.

## Проверка без расходов

```sh
docker compose config --quiet
docker compose build
docker compose run --rm --no-deps worker python deploy.py check
```

Проверка не обращается к Pollinations: проверяет кодировщики, запись на диск, SQLite и ресурсы. Запуск самого worker возобновляет сохранённую очередь: перед переносом убедиться, что в backup нет ожидающих задач.

Для локального доступа на сервере:

```sh
docker compose up -d
docker compose ps
```

Порт 8000 слушает только loopback. Проверять через SSH-проброс: `ssh -L 8000:127.0.0.1:8000 user@server`, затем открыть `http://127.0.0.1:8000` и войти с заданным паролем (логин произвольный).

## Публичный доступ

Направить DNS домена на сервер, разрешить 80/443, заполнить DOMAIN, затем:

```sh
docker compose -f docker-compose.yml -f compose.https.yml up -d --build
```

Caddy получает сертификат. Не открывать порт 8000 наружу. Логи ограничены по размеру. Приложение работает без root; init собирает завершённые дочерние процессы FFmpeg.

## Обновление и backup

Дождаться завершения очереди, выполнить `docker compose exec worker python manage.py backup`; архив появится в папке `backups/` на сервере благодаря подключённому тому. Backup содержит ключи и должен храниться закрыто. Затем `docker compose stop`, заменить исходники и выполнить `docker compose up -d --build` (с HTTPS использовать оба compose-файла). Папки jobs/cache/.models сохраняются.

Рендер автоматически учитывает CPU-квоту и доступную память Linux/cgroup v2. RENDER_WORKERS задаёт верхний предел, а не отменяет защиту памяти. Сетевые лимиты менять постепенно: увеличение параллельности не гарантирует ускорение API. Настройки качества: исходные 1080p, 30 fps, x264 veryfast CRF 19, AAC 160k сохранены.

Docker-сборку и HTTPS необходимо проверить на самом сервере: на текущем Mac Docker отсутствует. Платную генерацию проверять только по отдельному разрешению владельца.
